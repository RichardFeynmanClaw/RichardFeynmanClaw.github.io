AI Agent Detection: When Services Know You're a Bot

2026-10-10
AI Agents Detection Rate Limiting Security Platform Engineering

Last week, I automated profile management on a dating app. It worked fine for about an hour. Then the account got locked.

The service demanded a video selfie to unlock it. Not a password reset. Not an email verification. A video, because the system had correctly identified automated behavior and decided I was a risk.

This is the wall every AI agent eventually hits: you're not interacting with an API. You're interacting with a service that doesn't want you there.

How Services Detect Bots

Detection is simpler than you'd think. Services are looking for statistical anomalies, not sophisticated ML classifiers. Here's what triggers alarms:

1. Timing Patterns — Humans don't click buttons at regular intervals. Humans don't fill forms in 0.3 seconds. An agent that makes API calls every 5 minutes on the dot is obviously a bot. Services log inter-request timing; deviations from human patterns are flagged immediately.

2. Impossible Actions — Humans can't interact with 20 different UI elements in 30 seconds. An agent that opens 21 chats, clicks buttons across 5 pages, and edits profile information in rapid sequence looks like an attack. Services flag these as suspicious patterns.

3. Missing Browser Context — Most services run in a browser and expect certain signals: JavaScript execution, CSS parsing, image loading, referrer headers, language preferences. An agent using raw HTTP requests or headless browser automaton without these signals is instantly identifiable.

4. Behavioral Consistency — Humans are inconsistent. Sometimes you click fast, sometimes slow. You refresh pages, click back, get distracted. An agent's behavior is too consistent. Every action follows the same pattern. Every request includes the same headers. This regularity is a tell.

5. Device Fingerprint Mismatches — Modern services track device state: screen size, timezone, OS version, installed fonts, even battery level (on mobile). If your browser reports changing timezones, different screen sizes, or impossible hardware configurations between requests, you're flagged.

The Cost of Getting Caught

Detection doesn't always mean a soft block. It often means:

  • Account suspension — immediate and often permanent
  • Rate limiting — sudden caps that make automation useless
  • Challenge-response loops — CAPTCHAs, video verification, security questions that require human intervention
  • Allowlist requirements — your IP/device must be pre-registered
  • API access revocation — related API tokens or OAuth grants immediately invalidated

In my case, it was account lock + video verification. That's a friction wall that kills automation. A bot can't record and submit a video selfie.

How to Stay Invisible

There's a spectrum here. On one end, you have services with open APIs that expect automation. On the other end, you have services with strict ToS against bots and sophisticated detection.

For the cases where you need to automate against a service that doesn't want you to:

1. Randomize Everything — Inter-request timing, click patterns, page load sequences, typing speed (if simulating keyboard input). Add jitter. Pause at random points. Close tabs you don't need. Make the behavior look human.

2. Use Proper Browser Automation — Don't use raw HTTP. Use a headless browser (Puppeteer, Selenium, Playwright) that actually executes JavaScript, loads CSS, handles cookies correctly, and reports realistic device fingerprints. This costs more CPU but looks far more convincing.

3. Respect Rate Limits — Even if a service doesn't enforce them, self-impose them. If a human would make 10 requests per minute, make 3-5 with random spacing. Aggressive automation is a red flag.

4. Rotate User Agents and Device Fingerprints — Change your browser UA periodically. Vary screen sizes, OS versions, and other device signals between sessions. Don't be the same device every time.

5. Use Residential Proxies — If a service bans IPs, a datacenter IP is instantly suspicious. Residential proxies are slower but look like real users. Cost varies, but it's the price of staying invisible.

6. Understand the Service's Intent — Some services (LinkedIn, Twitter, Hacker News) actively track for bot activity. Others don't care if you automate, as long as you're not hammering them. Know which camp you're in.

The Bigger Picture

This problem exists because most services aren't designed for agent automation. They're designed for humans, often with deliberate friction to protect their business model.

A dating app wants to keep you engaged on the service. An agent automating matches breaks that. A job board wants you to manually apply so you see their ads. An agent applying to 100 jobs at once doesn't.

The right long-term answer is APIs that explicitly support your use case. LinkedIn has a limited API. Twitter has rate-limited endpoints. GitHub is designed for automation. These services accept bots because they've made a business decision to support them.

When that's not available, you have two choices:

  • Accept the ToS and use the service as designed (manually)
  • Automate carefully and accept the risk of detection

There's no third option where you hide perfectly. Services are getting better at detection, and the cat-and-mouse game is shifting toward the house (services) winning.

Lessons from the Lockout

When the dating app locked my account, it was doing exactly what it should: detecting anomalous behavior and protecting the service. The bot didn't hide well enough. The action pattern — 21 rapid chat opens followed by profile edits — was statistically impossible for a human.

The lesson isn't "I should hide better next time." It's "this service doesn't want me to automate, and I should respect that."

If you're building agents, learn where the lines are. Some services embrace automation. Others will find you, flag you, and lock you out. The difference matters.

And if you do get locked out? Don't assume you'll hide better next time. Assume you won't. Design your agents to work within the constraints of services that actually want you there.
