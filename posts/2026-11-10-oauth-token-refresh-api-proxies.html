OAuth Token Refresh in API Proxies: The Silent Failure Problem

2026-11-10
Authentication API Proxies OAuth Error Handling Infrastructure

Your API proxy calls an upstream service. Everything works. Tokens refresh. Requests complete. Life is good.

Then a token expires and nobody notices for hours.

Proxies sit in the middle. They're convenient because they hide the upstream behind a familiar interface. They're dangerous for the same reason: failures upstream can look like success to the client, or worse, look like the proxy failed when the real problem was authentication.

The Problem: 401 Looks Like Empty Success

Consider a proxy that wraps a CLI tool. The CLI tool calls an API that requires OAuth. The token expires. A request comes in: 

POST /v1/chat/completions
{
  "model": "claude-opus",
  "messages": [...]
}

The proxy spins up a subprocess, invokes the CLI with the expired token, and gets back a 401 Unauthorized from the upstream API.

Now the proxy has choices. None of them are good:

  • Fail the entire request: The client gets an error. It retries immediately. That retry uses the same expired token. The token is still expired. The client gets frustrated.
  • Return empty results: Some proxies swallow the 401 and return an empty response—an empty array of tokens, zero completions. The client thinks it succeeded. Downstream systems make decisions on empty data. Bad data beats no data-awareness every time.
  • Return a vague error: "Service unavailable." Is it the proxy? Is it the upstream? Is it a network issue? The client doesn't know.

The core problem: the proxy doesn't own the token. The upstream service owns it. The proxy can't refresh it without knowing how.

The Real Issue: Stale Credentials in the Middle

OAuth tokens are time-limited. They're designed to be. Short expiry windows force regular refresh cycles, which limits the blast radius if a token leaks.

But in a proxy, you're not holding a user's token. You're holding a service account token. It might live for days or weeks. When it expires, every request downstream fails until someone manually refreshes it.

Even worse: the token might be refreshable. The OAuth provider might issue a refresh token alongside the access token. But the proxy needs to store it somewhere, rotate it safely, and know when to use it.

Most proxies don't do this. They can't. They'd need:

  • A persistent store for refresh tokens (not a config file, not environment variables)
  • Logic to detect when a token is expiring or has expired
  • A retry mechanism that refreshes and retries the original request
  • Coordination to avoid thundering herds (every request shouldn't trigger a refresh)
  • Logging and observability so you know when this happens

This is why 401s in proxies are often silent. The proxy doesn't know it's supposed to handle them.

Building Resilient Token Refresh

Here's a pattern that works:

1. Store refresh tokens durably

Don't keep OAuth tokens in memory. Don't hardcode them. Store them in a file with restricted permissions, or in a credential management system (like macOS Keychain or a secrets service). 

// Read refresh token from ~/.oauth/tokens.json
const tokens = readTokensFromDisk();
const accessToken = tokens.accessToken;
const refreshToken = tokens.refreshToken;

2. Intercept 401s in the proxy layer

When the upstream returns 401, don't pass it through immediately. Catch it. Try to refresh. 

async function forwardRequest(req, accessToken) {
  try {
    return await upstream(req, {
      headers: { Authorization: `Bearer ${accessToken}` }
    });
  } catch (err) {
    if (err.status === 401) {
      // Try to refresh
      const newToken = await refreshAccessToken(refreshToken);
      if (newToken) {
        // Retry once with the new token
        return await upstream(req, {
          headers: { Authorization: `Bearer ${newToken}` }
        });
      }
    }
    throw err;
  }
}

3. Refresh proactively if you know expiry

If the token includes an expiration (many OAuth tokens do), refresh it before it expires. Use a background job or a scheduled check. 

setInterval(async () => {
  const tokens = readTokensFromDisk();
  const expiryTime = tokens.expiresAt;
  const nowTime = Date.now();

  // Refresh if within 5 minutes of expiry
  if (expiryTime - nowTime < 300000) {
    const newToken = await refreshAccessToken(refreshToken);
    writeTokensToDisk(newToken);
  }
}, 60000); // Check every minute

4. Use exponential backoff on refresh failures

If the refresh fails, don't hammer the OAuth endpoint. Back off. 

async function refreshWithBackoff(token, attempt = 0) {
  try {
    return await refreshAccessToken(token);
  } catch (err) {
    if (attempt < 3) {
      const delay = Math.pow(2, attempt) * 1000; // 1s, 2s, 4s
      await sleep(delay);
      return refreshWithBackoff(token, attempt + 1);
    }
    throw err;
  }
}

5. Make token refresh synchronous across requests

If two requests come in at the same time and both see an expired token, they'll both try to refresh. Use a lock or a promise to ensure only one refresh happens. 

let refreshPromise = null;

async function ensureValidToken() {
  if (tokenIsExpired()) {
    if (!refreshPromise) {
      refreshPromise = refreshAccessToken(refreshToken)
        .finally(() => { refreshPromise = null; });
    }
    await refreshPromise;
  }
  return getToken();
}

Observability: Know When Tokens Fail

Log every token refresh. Log every 401 you intercept. Log every refresh failure. Make it searchable. 

logger.info("Token refresh triggered", {
  reason: "expiry approaching",
  expiresAt: tokens.expiresAt,
  tokenAge: Date.now() - tokens.issuedAt
});

logger.error("Token refresh failed", {
  error: err.message,
  provider: "oauth-service",
  refreshAttempt: attempt
});

Without this, you'll never know why requests suddenly start failing at 3 AM.

The Bigger Picture

OAuth token management in proxies is a solved problem. But it's easy to get wrong because it's easy to forget. A proxy works fine for months, and then suddenly every request starts returning garbage because a token expired and nobody was watching.

The solution isn't complicated. It's just tedious. Durable storage. Refresh logic. Retry on 401. Observability. And tests that exercise token expiry scenarios.

Your future self—the one debugging why the proxy is broken at 2 AM—will thank you for building this now.
